# MDS Dataspace Profile — 2026/1

> **Status — DRAFT.** This document specifies profile version `2026/1` of the Mobility Data Space dataspace profile. It is not yet released.

## Introduction

This profile specifies how the Mobility Data Space works: what its participants, the MDS Authority and the MDS Trusted Issuers each do. It builds on the **Dataspace Protocol 2025-1** (DSP) and the **Decentralized Claims Protocol 1.0** (DCP), and covers:

- the MDS entities: the MDS Authority, which governs the dataspace, and the MDS Trusted Issuers, which issue the MDS credentials;
- the MDS credentials: what an MDS Trusted Issuer issues and how a participant verifies it ([MDS Verifiable Credentials](https://mobility-data-space.github.io/mds-profile/2026/1/credentials/));
- for participants:
  - the protocol binding: DSP over HTTPS, with the DSP context only;
  - the participant DID document: a `did:web` DID and the service endpoints it advertises;
  - the MDS usage policies ([MDS ODRL Profile](https://mobility-data-space.github.io/mds-profile/2026/1/policy/));
  - the MDS data offers vocabulary ([MDS Data Offers Vocabulary](https://mobility-data-space.github.io/mds-profile/2026/1/vocabulary/)).

## MDS Authority and issuers trusted by MDS

The **MDS Authority** governs the dataspace: it decides which participants are members and which groups they belong to.

Trusted issuers are:

- The "MDS Trusted Issuer": `did:web:issuer.mobility-dataspace.eu`.

The trusted issuers are responsible for issuing the MembershipCredential and the GroupMembershipCredential, specified in [MDS Verifiable Credentials — 2026/1](https://mobility-data-space.github.io/mds-profile/2026/1/credentials/).

A participant **MUST** only trust issuers trusted by MDS for these two MDS credential types.

## A Participant DID document

Each MDS participant is identified by a Decentralized Identifier (DID) of the [`did:web` method](https://w3c-ccg.github.io/did-method-web/). A participant's DID **MUST** be a `did:web` DID under a domain the participant controls, for example `did:web:identity.mobility-provider.example`. A participant **MUST** use this DID as its participant identifier in the Dataspace Protocol. It is the `credentialSubject.id` of its MDS credentials and the value the `ParticipantId` policy operand is evaluated against.

### Service endpoints

A participant's DID document advertises the services other participants need to reach it, as entries of its `service` array (see [DID Core, §5.4](https://www.w3.org/TR/did-core/#services)).

**Data Service.** Participants **SHOULD** publicize each of their connectors in their DID document, following [Discovery of Service Endpoints](https://eclipse-dataspace-protocol-base.github.io/DataspaceProtocol/2025-1/#discovery-of-service-endpoints) in the Dataspace Protocol `2025-1`. In this case:

- the participant **MUST** add one entry per connector to the `service` array, with the `id`, `type` and `serviceEndpoint` properties;
- the entry's `type` **MUST** be `DataService`;
- the entry's `serviceEndpoint` **MUST** be the connector's [version metadata endpoint](https://eclipse-dataspace-protocol-base.github.io/DataspaceProtocol/2025-1/#exposure-of-dataspace-protocol-versions), i.e. the URL ending in `/.well-known/dspace-version`. A consumer resolves the `2025-1` protocol endpoints of the connector from the response of that endpoint.

The following example shows the `service` array of a participant running one connector:

```json
{
  "service": [
    {
      "id": "did:web:identity.mobility-provider.example#connector-1",
      "type": "DataService",
      "serviceEndpoint": "https://connector.mobility-provider.example/api/dsp/.well-known/dspace-version"
    }
  ]
}
```

## MDS usage policies

The ODRL profile is specified in [MDS ODRL Profile — 2026/1](https://mobility-data-space.github.io/mds-profile/2026/1/policy/). It defines four left operands in `https://w3id.org/mobility-dataspace/2026/1/policy/` (`Membership`, `ParticipantId`, `Group`, `EvaluationTime`), the operators and right operands each allows, and what each is evaluated against.

## MDS data offers vocabulary

The data offers vocabulary is specified in [MDS Data Offers Vocabulary — 2026/1](https://mobility-data-space.github.io/mds-profile/2026/1/vocabulary/). It says which mobilityDCAT-AP properties describe an MDS asset, which are required and which values some of them take, and which datasets a provider may list in its catalog.
